# Updating the engine patch set

1. Select a supported CEF branch and a complete Chromium maintenance revision.
   Review the CEF compatibility file and Chromium's full maintenance delta.
   Update CEF, Chromium and depot_tools commits, the official automate script
   digest, security assessment and reference versions in the manifest. Do not
   substitute a similarly named binary or silently advance a dependency.
2. Acquire into a new disk-backed native Linux workspace. Keep codec-enabled
   development and open-codec builds separate. The driver verifies every Git
   dependency listed by gclient after sync; a partially initialized Git folder
   must never count as an acquired dependency.
3. Obtain the exact affected upstream files from those commits. Keep them in
   an explicit snapshot directory, using the names consumed by
   `scripts/prepare-patches.py`. Regenerate, then review the complete diff and
   SHA-256 manifest changes. New Majoris source lives in `engine/src/`, rather
   than copied Chromium implementations. Preserve original upstream notices
   in patch context and add attribution for any newly reused Brave code.
4. Run `tests/test_engine.py --workspace WORKSPACE`. It checks pinned HEADs,
   exact applicability, a pristine disposable application/reversal, corrupted
   patches and the development-codec packaging boundary. Also run
   `scripts/build.py --stage patch ...`; it fails on checksum or context errors.
   Never use fuzzy application, ignore a rejected hunk or remove a test to
   make an upgrade pass.
5. When iterating in a dedicated source workspace, stop that workspace's build
   first. Preserve the previously applied patch bytes, check their exact
   reverse application, then reverse and apply the reviewed replacements.
   The main application checkout is not reset. A fresh workspace is preferable
   for upstream upgrades. CEF's own supported patcher remains responsible for
   its upstream integration patches.
6. Build with the supported automate workflow. The local adapter's digest,
   source-diff digests, complete GN flags, manifest and patch hashes are recorded.
   SDK creation rejects changed source/configuration or a missing successful
   build receipt. Review diffs generated by CEF as well as Majoris changes.
7. Rebuild the wrapper through the existing bootstrap and run all 27 Majoris
   suites against the prepared SDK. Supply original generated media fixtures
   using `MAJORIS_MEDIA_FIXTURES`, and require the codec build with
   `MAJORIS_EXPECT_PROPRIETARY_CODECS=1`. Validate actual H.264 frames, AAC samples,
   combined MP4 playback, native PiP pixels/identity/lifecycle, real AX/AT-SPI
   actions, history restore and task refresh. Keep the standard SDK fallback
   passing as a separate regression run.
8. Build and verify Debian packages and their extracted runtime. The custom
   SDK library hash must match its build provenance. Development package opt-in
   does not grant codec redistribution approval. Record compiler/runtime,
   fixture provenance, exact artifact digests, logs and remaining target checks.

The extension API is separate from CEF's generated public C++ API. Increment
its ABI version if an existing signature, structure or semantic contract changes.
New capability bits must correspond to implemented runtime paths, never build
flags alone. Add negative tests for unsupported runtimes, stale documents,
wrong browser/profile ownership, private views and invalid serialized input.

The source patches rely on Chromium internals. Review these upgrade surfaces:

* Alloy video-PiP support gate and native overlay factory/lifetime.
* Linux Widget::InitParams identity fields and launcher desktop-name format.
* AX tree serialization/reset semantics, RenderFrameHost document tokens,
  WebContents ownership and AX action enums. The OSR validation cache must not
  depend on a native accessibility manager that tree-only mode does not create.
* SerializedNavigationEntry pickle format, password sanitization, PageState
  validation and NavigationController's unused-controller restore contract.
* Task observer refresh flags, metric units, live task IDs and process sharing.
* GTK's public accessible/widget-action/editable interfaces. The local Vala
  binding describes GtkEditable's actual C interface; it does not fork GTK.

Security qualification, codec redistribution approval and target desktop
verification are independent decisions. Compilation or patch applicability
alone establishes none of them.
